## Mock-interview mode

Once the tiers above feel solid, simulate real conditions:

1. Pick a random problem from Tier 1 or 2 you haven't seen in a few days.
2. **State the recognition heuristic out loud first** — what in the problem statement signals the pattern — before writing any code. This is the actual skill this whole track is built around; skipping straight to code hides whether you'd have recognized the pattern cold, on an unseen problem, in a real interview.
3. State the brute force and its complexity, out loud, even if you don't write it.
4. Code the optimized solution.
5. State final time/space complexity, and why.
6. Answer the problem's **follow-up** from its part file, cold — this is where an interviewer actually distinguishes a memorized solution from real understanding.

If any step trips you up, that's real signal — go back to that pattern's part, re-read the recognition heuristic section at the top, and try a fresh random problem from the same pattern before moving on.
