<a name="styles"></a>
# 1. The three styles of the `fs` API

The same operation comes in three flavours:

```js
// ① Promise style — use this in application code ✅
import { readFile } from 'node:fs/promises';
const text = await readFile('notes.txt', 'utf8');

// ② Callback style — the original API, still everywhere in older code
import fs from 'node:fs';
fs.readFile('notes.txt', 'utf8', (err, text) => { /* ... */ });

// ③ Sync style — BLOCKS the event loop
const text2 = fs.readFileSync('notes.txt', 'utf8');
```

| Style | Blocks the server? | Use it for |
|---|---|---|
| `fs/promises` | no | request handlers, anything at runtime |
| callback | no | older code; same speed as promises |
| `*Sync` | **yes** | startup only (loading config once), CLI scripts |

> 🧠 **Remember:** **Sync only before `listen()`.** Once the server accepts traffic, a sync file call freezes every user ([Part 1 §12](01-javascript-execution-model.md)).

The `node:` prefix (`'node:fs'`) means "the built-in module" — it can never be confused with an npm package of the same name. Use it.

<a name="everyday"></a>
# 2. The everyday operations

```js
import { readFile, writeFile, appendFile, mkdir, readdir, stat, rm, rename, access } from 'node:fs/promises';

await writeFile('out/report.json', JSON.stringify(data));     // create or overwrite
await appendFile('app.log', 'line\n');                         // add to the end
await mkdir('out/2026/11', { recursive: true });               // make all folders; no error if they exist
const names = await readdir('uploads');                        // file names in a folder
const info  = await stat('video.mp4');                         // info.size, info.isDirectory(), info.mtime
await rename('tmp.txt', 'final.txt');                          // move / rename
await rm('out', { recursive: true, force: true });             // delete a folder and everything in it
```

**"Does this file exist?"** — don't check first and then open. Between the check and the open, the file can appear or vanish (a race). Just try the operation and handle the error:

```js
try {
  const text = await readFile(path, 'utf8');
} catch (err) {
  if (err.code === 'ENOENT') return null;   // file not found — expected
  throw err;                                // anything else is a real problem
}
```

Error codes worth knowing: `ENOENT` (no such file), `EACCES` / `EPERM` (no permission), `EEXIST` (already exists), `EISDIR` (it's a folder), `EMFILE` (too many open files — usually a leak of open file handles).

**Big files:** `readFile` loads the whole thing into memory and refuses files over 2 GiB. For anything large, use streams: `fs.createReadStream` / `createWriteStream` with `pipeline()` ([Part 9.5](09.5-streams-deep-dive.md)).

<a name="path"></a>
# 3. ⭐ Paths: `path.join` vs `path.resolve`

**Never build paths by gluing strings with `/`.** Windows uses `\`, double slashes creep in, `..` isn't cleaned up. Use the `path` module.

```js
import path from 'node:path';

path.join('uploads', 'user1', '../avatar.png');   // 'uploads/avatar.png' — joins + cleans up
path.resolve('uploads', 'avatar.png');            // '/home/app/uploads/avatar.png' — ABSOLUTE, from cwd
path.basename('/a/b/photo.jpg');                  // 'photo.jpg'
path.extname('photo.jpg');                        // '.jpg'
path.dirname('/a/b/photo.jpg');                   // '/a/b'
```

| | `path.join` | `path.resolve` |
|---|---|---|
| Result | relative or absolute — whatever you gave it | **always absolute** |
| Starting point | none — just joins the pieces | the current working directory (`process.cwd()`) |
| A piece starting with `/` | treated as just another piece | **restarts from that piece** (`resolve('/a', '/b')` → `/b`) |

> 🧠 **Remember:** `join` = **glue the pieces**. `resolve` = **"where exactly is this on disk?"**

<a name="dirname"></a>
# 4. ⭐ `__dirname`, `process.cwd()`, and ES modules

Two different "current folders":

| | Means | Changes when... |
|---|---|---|
| `__dirname` | the folder **this source file** is in | never — it's fixed by where the file lives |
| `process.cwd()` | the folder you **ran `node` from** | you start the app from somewhere else |

```js
// ❌ relative to wherever someone ran `node` — breaks with `cd /; node /app/src/index.js`
readFile('./templates/email.html');

// ✅ relative to THIS file — works from anywhere
readFile(path.join(__dirname, 'templates', 'email.html'));
```

**In ES modules there's no `__dirname`.** Use:

```js
import.meta.dirname    // Node 20.11+ / 21.2+ — same as __dirname
import.meta.filename   // same as __filename

// older Node:
import { fileURLToPath } from 'node:url';
const __dirname = path.dirname(fileURLToPath(import.meta.url));
```

<a name="atomic"></a>
# 5. Writing files safely (atomic writes)

`writeFile` overwrites a file **in place**. If the process crashes halfway, or two writes overlap, you're left with a **half-written, corrupted** file — a broken `config.json`, a truncated cache.

**The fix: write to a temporary file, then rename it.** A rename on the same disk is atomic — readers see either the old file or the new one, never half of one.

```js
async function writeFileAtomic(file, data) {
  const tmp = `${file}.${process.pid}.${Date.now()}.tmp`;
  await writeFile(tmp, data);
  await rename(tmp, file);     // swap in one step
}
```

(The `write-file-atomic` package does this plus the edge cases.)

**But really:** if several server instances need the same data, it shouldn't be in a local file at all. Local disk isn't shared between instances and often disappears when a container restarts. Use a database, Redis, or object storage (S3) — see [Part 6.7](06.7-file-uploads.md).

<a name="watch"></a>
# 6. Watching files

```js
import { watch } from 'node:fs/promises';
for await (const event of watch('./config')) console.log(event.eventType, event.filename);
```

`fs.watch` behaves differently on each operating system (duplicate events, missing file names on some platforms). For tooling, the `chokidar` package smooths this over. For **restarting your app on code changes**, use `node --watch app.js` (built in since Node 18.11/20) instead of nodemon ([Part 15](15-modern-node-features.md)).

<a name="security"></a>
# 7. Security: never trust a file name from a user

**Path traversal:** a user sends a "file name" like `../../etc/passwd`, and your code happily serves it.

```js
// ❌ GET /files?name=../../etc/passwd  → reads a system file
app.get('/files', (req, res) => res.sendFile(path.join(UPLOAD_DIR, req.query.name)));
```

```js
// ✅ resolve, then CHECK the result is still inside the folder you meant
app.get('/files', async (req, res) => {
  const base = path.resolve(UPLOAD_DIR);
  const target = path.resolve(base, String(req.query.name));
  if (!target.startsWith(base + path.sep)) return res.status(400).end();   // escaped the folder
  res.sendFile(target);
});
```

Better still:
- **Don't use user-supplied names for storage at all.** Save uploads under a generated id (`crypto.randomUUID()`) and keep the original name in the database ([Part 6.7](06.7-file-uploads.md)).
- Express's `res.sendFile(name, { root: UPLOAD_DIR })` also refuses to leave `root`.

More attacks of this kind: [Part 7.5 §4](07.5-security-beyond-auth.md).

<a name="interview"></a>
# 8. Interview Questions & Answers

### Q1. `fs.readFile` vs `fs.readFileSync` vs `fs/promises`?
> "Same work, different waiting. The sync one blocks the event loop until the file is read — fine at startup, never in a request handler. The callback and promise versions hand the read to the thread pool and keep the event loop free; I use `fs/promises` with `await` in modern code."

### Q2. `path.join` vs `path.resolve`?
> "`join` just glues path pieces together and normalizes them — the result can still be relative. `resolve` always returns an absolute path, starting from the current working directory, and a piece starting with `/` resets it. I use `join` to build a path and `resolve` when I need to know exactly where it is on disk — for example, to check it's inside an allowed folder."

### Q3. `__dirname` vs `process.cwd()`?
> "`__dirname` is the folder the current source file is in — it never changes. `process.cwd()` is where the process was started from, which depends on how someone launched it. Paths to your own files should be built from `__dirname` — or `import.meta.dirname` in ES modules — so they don't break when the app is started from a different folder."

### Q4. How do you check if a file exists?
> "I don't check first — that's a race, because the file can change between the check and the use. I just try the operation and handle `ENOENT`. If I only need existence, `fs.promises.access` or `stat` inside a try/catch."

### Q5. How do you prevent a crash from leaving a half-written file?
> "Write to a temporary file in the same folder and then `rename` it over the real one. Rename is atomic on the same filesystem, so readers see the old version or the new one, never a partial file."

### Q6. How do you serve a user-requested file safely?
> "Never pass the user's name straight into a path. Resolve the full path and check it still starts with the allowed folder, so `../../etc/passwd` is rejected. Better, store files under generated ids and look up the id — then a user-supplied name never touches the filesystem."

<a name="cheatsheet"></a>
# 9. Cheat Sheet

```
fs/promises + await  → app code ✅
callback fs          → old code, same speed
*Sync                → startup / CLI only (blocks everyone)
use 'node:fs' prefix

exists? → don't check first; try it, catch err.code === 'ENOENT'
codes: ENOENT missing · EACCES no permission · EEXIST exists · EMFILE too many open files
big files → streams (readFile refuses > 2 GiB)

path.join    = glue pieces (may stay relative)
path.resolve = absolute, from cwd; '/x' piece restarts
never build paths with '/' string concatenation

__dirname = this file's folder (fixed) · process.cwd() = where node was launched (varies)
ESM: import.meta.dirname / import.meta.filename

atomic write = write tmp file → rename over the real one
shared data across instances → DB / Redis / S3, not local disk

user file names: resolve → check startsWith(base + sep) → or store by generated id
```
