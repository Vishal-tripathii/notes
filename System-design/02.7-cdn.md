# 1. Analogy + what & why

## Analogy 🍕
A pizza chain with **one kitchen in New York**: a Tokyo order ships from NY → cold, hours late. Instead the chain opens **local branches in every city** → Tokyo's order comes from a Tokyo kitchen → hot, fast.

> **A CDN is those local branches for your content** — copies of your files stored in servers worldwide, so each user is served from one *near them*, not from your one faraway origin.

## What & why
**A CDN (Content Delivery Network) is a globally distributed network of servers that cache your content close to users**, cutting latency and offloading your origin.

Problem it solves: **distance = latency (Part 3)**. A user in India hitting a US server pays a big round-trip cost on *every* file. A CDN puts a copy nearby → short trip.
```
WITHOUT CDN:  [User in Tokyo] ──────────6000 miles──────────▶ [Origin server, USA] 🐌
WITH CDN:     [User in Tokyo] ──50 miles──▶ [CDN edge, Tokyo] ⚡  (origin untouched)
```

---

<a name="need"></a>
# 2. The need (why it matters)

1. **Lower latency** — served from a nearby **edge server**, not across the globe.
2. **Less origin load** — CDN absorbs most requests → origin does far less work (a caching layer, Part 5).
3. **Handles traffic spikes** — a viral post / product launch served by hundreds of edge servers, not one origin.
4. **Availability & DDoS protection** — the distributed network absorbs attacks and survives origin hiccups.

---

<a name="static"></a>
# 3. Static assets (the classic CDN use)

CDNs are perfect for **static content** — files identical for everyone:
- Images, videos, CSS, JavaScript, fonts, downloads.

Same for all users → caching a copy at the edge is safe and hugely effective. Dynamic per-user content (bank balance, personalized feed) is *not* typically CDN-cached (though modern CDNs offer dynamic acceleration).
```
Static (CDN-friendly):  logo.png, app.js, styles.css, product-video.mp4
Dynamic (usually not):  personalized feed, account balance
```

---

<a name="global"></a>
# 4. Global distribution (how it works)

The CDN has hundreds of **edge servers** (aka **PoPs — Points of Presence**) worldwide. On a request:
```
1. Request goes to the NEAREST edge server (via DNS/geo-routing).
2. Edge has it cached?  ✅ HIT → serve instantly from the edge.
3. Not cached?          ❌ MISS → fetch from ORIGIN once, cache at the edge,
                                   then serve. Next nearby user gets a HIT.
```
Same **cache hit/miss** model as Part 5 — spread across the globe. Freshness via **TTL / cache headers** (`Cache-Control`, Part 6); update on deploy by **purging** the CDN or using **versioned filenames** (`app.v2.js`).

# 5. Real examples

- **Netflix** — streams video from edge servers near you (its own CDN, *Open Connect*) → instant playback.
- **Instagram/Facebook** — photos & videos via CDN worldwide.
- **E-commerce (Amazon/Flipkart)** — product images/CSS/JS on a CDN; survives sale-day spikes.
- **Providers:** **Cloudflare, Akamai, AWS CloudFront, Fastly, Google Cloud CDN.**

<a name="free"></a>
# 6. Are CDNs free? (practical note)

Depends on **whose file** is on the CDN — two different things get called "using a CDN":

## Case 1: You loaded a *library* from a public CDN → free ✅
```html
<script src="https://cdnjs.cloudflare.com/ajax/libs/pdf.js/3.11/pdf.min.js"></script>
```
Public/free CDNs (**cdnjs, jsDelivr, unpkg, Google Fonts**) host popular **open-source libraries** for anyone to link to. You didn't set anything up — just referenced their URL.
**Why free:** they serve *the library* (same file for millions of sites), it's open-source, and the provider (Cloudflare/Fastly) sponsors it. You're not the one whose unique content is hosted.
> Like a **public library** — the books (open-source libs) are free to borrow; the library bought them, not you.

## Case 2: Your *own* file served via a CDN → someone pays 💰
Your unique `my-report.pdf` must be stored (origin: S3/your server) and distributed via a CDN account (CloudFront, Cloudflare, Bunny…). That account **isn't free by default** — CDNs charge mainly by **bandwidth** (GB downloaded). More downloads = higher bill.
**BUT** most have generous **free tiers:**
- **Cloudflare** — free plan covers a lot of bandwidth.
- **AWS CloudFront** — free tier (~1 TB/month for a year, then pay-as-you-go).
- **Bunny/Fastly** — cheap, usage-based.
So a small, lightly-trafficked file can genuinely cost **$0** — but because you're *within a quota*, not because CDNs are inherently free.

## "I didn't set it up" — likely one of:
- A **hosting platform** (Vercel, Netlify, Firebase) includes a CDN automatically and absorbs the cost in your plan.
- A **third-party viewer/service** hosts it (free tier or bundled pricing).

> **One-liner:** *Public CDNs serving open-source libraries are free (provider-sponsored). CDNs serving **your own** files cost money — charged by bandwidth — but usually have a free tier covering small usage. "Free" almost always means 'someone else's content' or 'within a free quota.'*

<a name="interview"></a>
# 7. Interview questions & answers

### Q: "What is a CDN and why use one?"
> *"A CDN is a globally distributed network of servers that cache your content close to users. You use it to cut latency — a user is served from a nearby edge server instead of your faraway origin — and to offload your origin, since the CDN absorbs most requests. It's ideal for static assets like images, CSS, JavaScript, and video, and it also helps handle traffic spikes and absorb DDoS attacks."*

### Q: "How does a CDN actually work?"
> *"When a user requests a file, they're routed to the nearest edge server. If that edge has the file cached, it's a hit and served instantly. If not, it's a miss — the edge fetches it from the origin once, caches it, and serves it, so the next nearby user gets a hit. It's the same cache hit/miss model as any cache, just distributed geographically, with TTLs and cache headers controlling freshness."*

### Q: "What should and shouldn't you put on a CDN?"
> *"Static content that's the same for everyone — images, video, CSS, JS, fonts — is perfect, because caching one copy at the edge serves everyone. Highly dynamic, per-user data like a personalized feed or an account balance usually shouldn't be CDN-cached, since it changes per request and staleness would be wrong — though modern CDNs do offer dynamic acceleration."*

### Q: "How do you update content on a CDN after a deploy?"
> *"Two common ways: set a TTL so cached copies expire and refresh automatically, or explicitly purge/invalidate the cache on deploy. In practice the cleanest trick is versioned filenames — like app.v2.js instead of app.js — so a new deploy requests a brand-new URL the CDN hasn't cached, avoiding stale files entirely."*

### Q: "CDN vs a normal cache like Redis?"
> *"Same idea — serve from a fast copy instead of the slow source — but different scope. Redis is an application-level cache near your servers, usually for dynamic data and database results. A CDN is a geographically distributed cache at the network edge, near users, for static assets. Redis reduces database load; a CDN reduces latency by distance and offloads your origin. Big systems use both."*

<a name="cheatsheet"></a>
# 8. Cheat Sheet

### Core
- **CDN** = globally distributed edge servers caching content near users.
- Analogy: local pizza branches vs one faraway kitchen.
- Solves **distance = latency** (Part 3); it's **caching (Part 5) + geography**.

### Why / need
Lower latency · offload origin · absorb traffic spikes · DDoS protection.

### What to cache
- ✅ Static, same-for-everyone: images, video, CSS, JS, fonts.
- ❌ Dynamic per-user: feed, balance.

### How it works
Nearest **edge (PoP)** → HIT serve / MISS fetch-from-origin-once-then-cache. Freshness via TTL / cache headers / purge / versioned filenames.

### Free or paid?
- **Public CDN + open-source library** (cdnjs, jsDelivr) → **free** (provider-sponsored).
- **Your own files** (CloudFront, Cloudflare) → **paid by bandwidth**, but free tiers cover light usage.
- Hosting platforms (Vercel/Netlify) bundle a CDN for free within your plan.

### Providers
Cloudflare, Akamai, AWS CloudFront, Fastly, Google Cloud CDN.
